# Redesign: ค่าจ้างรายชั่วโมง-นาที + ฟีเจอร์ Owner (สเปค)

> สถานะ: **ร่าง — รอพี่ปุ้ยคอนเฟิร์มข้อสมมติก่อนเริ่มเขียนโค้ด**
> เขียน 2026-05-21 จากคำสั่งของพี่ปุ้ย

## ทิศทางที่ตกลงแล้ว
- คงระบบ **สแกน 4 slot/วัน** เดิม — เปลี่ยนแค่วิธีคิดเงิน
- เวลาเริ่มงานมาตรฐาน **เดียวทั้งร้าน** ตั้งใน Config (default `08:00`) แก้ได้
- ปิดยอด & จ่ายเงิน ได้ทั้ง **รายวัน + รายเดือน** owner เลือกเอง
- เอา "ดูยอด" ออกจากเมนูพนักงาน → ย้ายไปเมนู owner (rich menu ทำแล้ว)

---

## 1) โมเดลคิดเงินใหม่

อ้างอิงค่าจ้างต่อวันของแต่ละคน (`daily_wage` รายบุคคล ถ้าไม่ตั้ง = `wage_default` = 400)

```
ต่อชั่วโมง = daily_wage / 8        (400/8 = 50 ฿/ชม)
ต่อนาที    = ต่อชั่วโมง / 60       (50/60 = 0.8333 ฿/นาที)
```

**ค่าจ้างฐานตาม day_type** (owner เลือกตอน /endtoday, default = เต็มวัน):
| day_type | ฐานค่าจ้าง |
|---|---|
| เต็มวัน (full) | `daily_wage` |
| ครึ่งวัน (half) | `daily_wage / 2` |
| กำหนดเอง N ชม (custom) | `ต่อชั่วโมง × N` (N = 1,2,3…) |
| ไม่มาทำงาน (absent) | 0 |

**หักมาสาย** (อ้างเวลาสแกน slot 1 = เวลาเข้างานจริง):
```
นาทีสาย = (เวลาสแกน slot1) − (work_start_time)
ถ้า นาทีสาย > late_grace_minutes (15):
    หัก = นาทีสาย × ต่อนาที        ← [ข้อสมมติ A — ดูด้านล่าง]
    แจ้ง owner ว่ามาสาย
ค่าจ้างสุทธิ = max(0, ฐานค่าจ้าง − หัก)
```

### ❓ ข้อสมมติที่ต้องคอนเฟิร์ม
- **[A] นับนาทีสายยังไง?** — สาย 20 นาที (grace 15) จะหัก
  - (A1) หักทั้ง 20 นาที (เกิน grace แล้วหักเต็ม) ← *ผมเลือกอันนี้ถ้าไม่บอก*
  - (A2) หักเฉพาะส่วนเกิน 5 นาที (20−15)
- **[B] ครึ่งวัน = `daily_wage/2`** ใช่ไหม (หรือ = 4 ชม × ต่อชม ซึ่งได้เท่ากัน ✓)
- **[C] หักมาสาย ใช้กับทุก day_type** (รวมครึ่งวัน/custom) หรือเฉพาะเต็มวัน?

## 2) เปลี่ยนแปลง Data Model (Sheets)

### Employees — เพิ่มคอลัมน์
| คอลัมน์ใหม่ | ความหมาย |
|---|---|
| `nickname` | ชื่อเล่น *(เพิ่มแล้ว รอ deploy)* |
| `daily_wage` | ค่าจ้าง/วัน รายบุคคล (ว่าง = ใช้ `wage_default`) |
| `terminated_at` | วันเลิกจ้าง (ว่าง = ยังทำงาน) — แทน/เสริม `is_active` |

### Config — เพิ่ม key
| key | default | ความหมาย |
|---|---|---|
| `wage_default` | 400 | ค่าจ้าง/วัน เริ่มต้น (ใช้เมื่อไม่ได้ตั้งรายคน) |
| `late_grace_minutes` | 15 | สายได้กี่นาทีก่อนเริ่มหัก |
| `work_start_time` | 08:00 | เวลาเริ่มงานมาตรฐาน |

> `wage_full_day` / `wage_half_day` เดิม → เลิกใช้ (คิดจากสูตรแทน)

### Checkins — เพิ่มคอลัมน์
| คอลัมน์ใหม่ | ความหมาย |
|---|---|
| `late_minutes` | นาทีที่มาสาย (จาก slot1) |
| `late_deduction` | จำนวนเงินที่หัก |
| `decided_by` / `decided_at` | owner ตัดสิน day_type ตอนไหน/ใคร |
> `day_type`, `wage`, `status` มีอยู่แล้ว — `wage` = ค่าจ้างสุทธิหลังหัก

### Payments — ปรับ
| เปลี่ยน | ความหมาย |
|---|---|
| `period` | รองรับทั้งรายวัน `2026-05-21` และรายเดือน `2026-05` |
| `slip_url` (ใหม่) | URL สลิปโอนเงิน (อัปตอน mark paid) |

## 3) Flow การเช็คอิน + Flex card (เปลี่ยน)

- พนักงานสแกนหน้าปกติ (4 slot) → response/card โชว์ **ชื่อ + ชื่อเล่น**
- Flex card หา owner ต่อการสแกน: ปุ่ม **[รับทราบ] / [ไม่มาทำงาน]**
  (เลิกใช้ปุ่ม approve เต็มวัน/ครึ่งวัน ต่อ-สแกน — ย้ายการตัดสิน day_type ไป /endtoday)
- ถ้า slot1 สาย > grace → การ์ดแจ้ง owner "มาสาย X นาที"

---

## 4) คำสั่ง + Trigger

| คำสั่ง/เวลา | ทำอะไร |
|---|---|
| `/today` | รายชื่อพนักงานที่เช็คชื่อวันนี้ทั้งหมด (ชื่อ+ชื่อเล่น+เวลาเข้า+สถานะสาย) |
| `/endtoday` หรือ **17:30** (cron) | เด้งเมนูให้ owner: รายชื่อคนมาทำงานวันนี้ → ต่อคนเลือก **day_type (เต็ม/ครึ่ง/1-2-3ชม)** + **จ้างต่อ / เลิกจ้าง** |

> 17:30 ใช้ time-trigger เดิม (Reminder.gs ทุก 5 นาที) เพิ่ม logic ใหม่

---

## 5) เมนู Owner (ขยาย) — admin.html + Admin.gs

1. **รายชื่อพนักงานทั้งหมด** — ชื่อ, ชื่อเล่น, เบอร์, เลขบัญชี, ค่าจ้าง/วัน, ยอดรวม
2. **รายชื่อที่ยังทำงานอยู่** (active) — ชื่อ, ชื่อเล่น
3. **แก้ค่าจ้างรายบุคคล** (`daily_wage`)
4. **ตั้งค่าระบบ** — `wage_default`, `late_grace_minutes`, `work_start_time`
5. **เลิกจ้างพนักงาน** → ปิดยอดวันนั้นทันที
6. **รายงานยอดจ่าย** เลือก รายวัน/เดือน/ปี
7. **ดูย้อนหลัง** รายวัน/เดือน/ปี — วันนั้นใครมา จ่ายเท่าไร (ชื่อ+ชื่อเล่น)
8. **รายละเอียดพนักงาน** — สถานะ(ทำงาน/เลิกจ้าง), มากี่ครั้ง, ได้เงินรวม, จ่ายวันไหน, สลิป
9. **ปิดยอดหลายคนพร้อมกัน** (bulk)
10. **mark จ่ายแล้วหลายคนพร้อมกัน** (bulk) + แนบสลิป

## 6) แผนทำเป็นเฟส (เสนอ)

| เฟส | เนื้อหา | ความเสี่ยง |
|---|---|---|
| **P1** | Data model + Config keys + ฟังก์ชันคิดเงินใหม่ (`computeWage_`) + unit ทดสอบ | ต่ำ — ไม่กระทบ UI |
| **P2** | Settings UI (owner ตั้ง wage_default/grace/work_start + แก้ค่าจ้างรายคน) | กลาง |
| **P3** | เปลี่ยน flex card + checkin response (ชื่อเล่น, รับทราบ/ไม่มาทำงาน, แจ้งสาย) | กลาง |
| **P4** | `/today`, `/endtoday` + cron 17:30 + เมนูตัดสิน day_type/จ้างต่อ | สูง |
| **P5** | เมนู owner: รายชื่อ/รายงาน/ย้อนหลัง/รายละเอียด | สูง |
| **P6** | ปิดยอดรายวัน + bulk close + bulk mark-paid + แนบสลิป | สูง |

> เสนอเริ่ม **P1** ก่อน (วาง schema + เครื่องคิดเงิน) เพราะทุกเฟสพึ่งมัน

## คำถามค้างก่อนเริ่ม
1. ข้อสมมติ **[A] [B] [C]** ด้านบน — เลือกแบบไหน
2. "เลิกจ้าง = ปิดยอดวันนั้นทันที" → ปิดเป็น Payment รายวัน (period = วันนั้น) ใช่ไหม
3. สลิปโอนเงิน — owner อัปโหลดรูปผ่านหน้า admin ตอน mark paid ใช่ไหม
